# Стиль маркдаун-документов по правилам хоккея

Эталон: `ХОККЕЙ ОСФ 26-27.md` (копия файла `ШТРАФЫ.md`, свёрстанного вручную). Все новые разделы правил оформлять так же.

## Эталонные файлы — НЕ ИЗМЕНЯТЬ

- `ХОККЕЙ ОСФ 26-27.md`, `ИСПРАВЛЕНИЯ.md`, `ФАКТЫ.md` — эталонные документы правил. **Без явного согласия пользователя не редактировать**, не «исправлять» и не переформатировать — даже если в тексте видны ошибки. Любые правки этих файлов вносит или одобряет только пользователь.
- Сгенерированные производные (`ХОККЕЙ ОСФ 26-27.html`, `index.html`, `facts/index.html`) пересобираются только из эталона — вручную их не править.

## Заголовки

- `# ПРАВИЛО N. НАЗВАНИЕ` — правило целиком, название капсом
- `## N.M. НАЗВАНИЕ ПУНКТА` — пункты правила, капсом
- `#### СИТУАЦИЯ N` — формулировка ситуации из кейсбука (нумерация внутри правила с 1)
- `#### РЕШЕНИЕ` — ответ на ситуацию; при нескольких вариантах — `#### РЕШЕНИЕ №1`, `№2`…
- Неприменяемые пункты: заголовок остаётся, в конце `— НЕ ПРИМЕНЯЕТСЯ`, тело пустое

## Текст

- Текст правил — обычные абзацы, без списков, если в оригинале это не нумерованный перечень
- Нумерованные критерии/условия — `1.`, `2.`…; буквенные подпункты — нативный список с буквой: `- **а)**`, `- **б)**`…
- `**ПРИМЕЧАНИЕ:**` — оговорки после решения или внутри правила

## Ссылки на другие правила

- Все ссылки на правила — всегда курсивом: `*Правило 15.2 абзац 2*`, `*Правило 76 Вбрасывание*`, `*Правиле 24.2 абзац 6*`
- Курсивом выделяется вся ссылка целиком: номер + «абзац N»/«пункт N» + название правила, если оно указано; цепочки через запятую (`*Правило 16, Таблица 11, Пример Ж12*`) — тоже целиком
- Точка после номера ставится только если она заканчивает предложение: `*Правило 15.2* и *Правило 15.5 абзац 3*.` — точек после цифр внутри предложения нет (`Правило 15.2 абзац 2`, не `Правило 15.2. абзац 2.`). Точки внутри самого номера (`15.2`) остаются. Нумерация заголовков `## 15.2.` и маркеры списков `1.` — не ссылки, точки сохраняются
- Отдельной строкой — цитатой-блоком: `> *Правило 16.2 Численное меньшинство.*` или `> _Дополнительную информацию см. в Приложении 4 — Справочные таблицы — Таблица 1._`

## Таблицы штрафов

Для раскладки штрафов по командам:

```markdown
| Команда А | Команда Б |
| --- | --- |
| №15 — 2 в 3:00 | №12 — 2 в 3:30 |
```

Штрафы записываются как `5+20`, `2 + 5+20`; время — `1:34`.

## Git

- После каждого завершённого изменения (правки документа, сборки, деплоя) делать `git add -A`, коммит с осмысленным сообщением и `git push` в `origin/main` — без отдельной просьбы пользователя
- Пустые коммиты не делать: если изменений нет — просто не коммитить

## Живые зачёты referees.fhr.ru

Когда пользователь присылает текст вопроса со страницы тестирования:

- **Сначала база, потом разбор.** Искать точное совпадение в `fhr_questions/questions.json` — по `id` из `question_NNNN_variant` (если есть в вставке) или по ключевым словам вопроса; сверять и формулировку, и набор вариантов. Ответ брать из карточки в `gen_answers.py`/`answers_1_1276.md` — карточки выверены по ключам прошлых сдач и приоритетнее пересчёта вживую. Анализировать по правилам только при отсутствии совпадения.
- **Формат ответа:** `Вариант N — <текст>` ✅, обоснование одной-двумя строками.
- **Медиа-вопросы:** искать по имени файла из `[MEDIA]`-URL (`/static/files/...`) в полях `photo`/`video`.
- **После сдачи:** разобрать каждый неправильный вопрос, определить ключ по правилам, исправить карточку в `gen_answers.py`, перегенерировать `questions/index.html`, дополнить `fhr_questions/exam_notes.md` (номер попытки, результат, разбор), задеплоить и запушить.

## Прочее

- В начале файла `## ОГЛАВЛЕНИЕ` — список правил со ссылками-якорями `#правило-N-название`; при добавлении новых правил дополнять

- Русский текст, терминология книги: «взятие ворот», «хоккеист», «главный судья», «овертайм»
- Игроки обозначаются `А №44`, `Б №6` (или `A6`, `Б7` в таблицах — как в исходнике)
